Sun-angle invariant

Illumination-normalised features

Why cross-reference at all

Chandrayaan‑2 frames are captured under mission-specific Sun angles and orbit geometry. Tying every frame back to LRO NAC / SELENE gives an independent geodetic check and lets features accumulate across missions instead of resetting with each pass.

What "multi-modal" means here

OHRC panchromatic, TMC‑2 pushbroom, and IIRS hyperspectral bands each encode surface reflectance differently. A match has to survive not just a rotation or a crop, but a change in sensor physics.

About / Documentation

System architecture

Data acquisition through to a registered product, and the stack behind it.

Recommended stack

React + TypeScript + Three.js / React Three Fiber on the client; FastAPI serving a PyTorch inference pipeline (OpenCV + NumPy for classical stages) on the backend. Model weights for SuperPoint, LightGlue and LoFTR are hot-swappable behind one inference interface, so the Hybrid engine can recombine components without a redeploy.

This build

What you're viewing is the frontend and interaction design layer for ISRO Problem Statement 26166, with a genuine in-browser classical feature-matching baseline (Harris-response corner detection, patch descriptors, ratio-test matching, RANSAC affine estimation) so the workflow is real and interactive even before the GPU backend is attached.

Problem statement

ISRO PS 26166 — multi-modal, Sun-angle and scale invariant image correspondence using Chandrayaan‑2 optical images (OHRC, TMC‑2, IIRS), registered against LRO NAC and SELENE reference imagery.
